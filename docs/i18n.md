# Idiomas del sitio público (next-intl)

Español (`es-AR`, sin prefijo: `/propiedades`) y portugués de Brasil (`pt-BR`, en `/pt`: `/pt/propiedades`). Solo el sitio público; el dashboard queda en español.

## Piezas

| Archivo | Qué hace |
|---|---|
| `i18n/routing.ts` | Idiomas, idioma por defecto y prefijos. |
| `i18n/navigation.ts` | `Link`, `useRouter`, `usePathname`, `redirect` que respetan el idioma. **En el sitio público se usan siempre estos**, nunca `next/link` ni los de `next/navigation` (de ahí sí: `notFound`, `useSearchParams`, `useParams`). |
| `i18n/request.ts` | Junta los mensajes de cada sección para el pedido. |
| `i18n/server.ts` | `initLocale(locale)` (primera línea de cada page/layout bajo `app/[locale]`) y `asLocale(locale)` (para `generateMetadata`). |
| `i18n/namespaces.ts` | Lista de secciones. Cada una es `messages/<idioma>/<sección>.json`. |
| `i18n/global.d.ts` | Tipos: una clave que no existe en `messages/es-AR` es error de `tsc`. |
| `proxy.ts` | Detecta el idioma y reescribe las URLs a `/[locale]/...`. |
| `scripts/check-messages.mjs` | Verifica que `pt-BR` tenga exactamente las claves de `es-AR`. |

## Cómo traducir un componente

**El español es la fuente de verdad.** Se agregan las claves en `messages/es-AR/<sección>.json` con el texto actual **sin cambiarlo**, y el componente las usa. `messages/pt-BR` lo completa un paso de traducción aparte: no se toca al extraer.

### Componente de servidor

```tsx
import { getTranslations } from "next-intl/server";

export default async function ZonasPage({ params }: { params: Promise<{ locale: string }> }) {
  initLocale((await params).locale);
  const t = await getTranslations("zones.index");
  return <h1>{t("title")}</h1>;
}
```

Subcomponentes de servidor del mismo archivo: `async function ZoneTile() { const t = await getTranslations("zones.index"); ... }`.

### Componente de cliente (`"use client"`)

```tsx
import { useTranslations } from "next-intl";

export function SiteHeader() {
  const t = useTranslations("common");
  return <button aria-label={t("header.openMenu")}>{t("header.menu")}</button>;
}
```

### Metadata

```tsx
export async function generateMetadata({ params }: { params: Promise<{ locale: string }> }): Promise<Metadata> {
  const t = await getTranslations({ locale: asLocale((await params).locale), namespace: "zones.index" });
  return { title: t("metaTitle"), description: t("metaDescription") };
}
```

Un `export const metadata` con texto se convierte en `generateMetadata` así.

### Server Actions

Los mensajes que vuelven al visitante se traducen dentro de la acción: `const t = await getTranslations("contact.form");` (el idioma sale del pedido). **Las notas de leads, los mails y los mensajes para los asesores quedan en español**: los lee el equipo, no el visitante.

### Listas fuera del componente

Opciones definidas a nivel de módulo (`const OPERATIONS = [{ value: "venta", label: "Venta" }]`): se deja el `value` y se cambia `label` por una clave; el texto se resuelve adentro del componente. Ejemplo real en `features/public/v2/SiteHeader.tsx` (`NAV_LINKS` con `key` y `t(\`nav.${link.key}\`)`).

## Claves

- `camelCase`, agrupadas por componente o bloque: `listing.filters.title`, `listing.card.forSale`, `property.contact.whatsapp`.
- Nombres por **significado**, no por texto: `emptyTitle`, no `noEncontramosPropiedades`.
- **Variables y plurales en formato ICU**, nunca concatenando:
  - `"from": "desde {price}"` → `t("from", { price })`
  - `"available": "{count, plural, one {# disponible} other {# disponibles}}"` → `t("available", { count })`
  - Si el texto tiene un link o negrita en el medio: `"terms": "Acepto los <link>términos</link>"` → `t.rich("terms", { link: (c) => <Link href="/x">{c}</Link> })`.
- Una frase entera por clave: no partir oraciones en pedazos, porque el orden cambia entre idiomas.

## Qué se traduce y qué no

**Sí:** todo texto visible y también `aria-label`, `alt`, `title`, `placeholder`, textos de `toast`, mensajes de validación que ve el visitante, metadata (título y descripción) y mensajes de WhatsApp precargados que manda el visitante.

**No:**
- Contenido de la base: títulos y descripciones de propiedades, nombres de tipos, amenities, ciudades y barrios.
- La marca (`BRAND.*`).
- Notas de leads y textos para asesores, `console.*` y comentarios del código (siguen en español).
- `app/global-not-found.tsx` (no tiene idioma).

## Formatos

- Precios y números: `formatPrice` y `toLocaleString("es-AR")` se dejan como están (en `pt-BR` se ven igual: punto de miles y coma decimal).
- Fechas que ve el visitante: `useFormatter()` (cliente) o `await getFormatter()` (servidor) → `format.dateTime(date, { day: "numeric", month: "long" })`. Toman el idioma del pedido.

## Textos compartidos

- `common.contactCta`: la etiqueta "Escribinos" de toda la landing. Reemplaza a `CONTACT_CTA_LABEL` de `content.ts`.
- Si hace falta un texto genérico que no existe en `common`, se agrega en **la sección propia** (no en `common.json`, que es del lote C), aunque se repita.

## Reparto de la migración

Cada lote es dueño de sus secciones de mensajes y de sus archivos; ninguno toca los del otro.

**Lote A: secciones `listing` y `property`**
- `app/[locale]/(public)/propiedades/page.tsx`, `propiedades/loading.tsx`, `propiedades/[slug]/page.tsx`, `propiedades/[slug]/loading.tsx`
- `features/properties/`: `ListingFilters`, `ListingBar`, `PropertyCard`, `PublicPropertiesMap`, `PublicMapView`, `LocationCombobox`, `PropertySearchCombobox`, `ImageGallery`, `ShareButton`, `DescriptionReadMore`, `KeyFacts`, `PropertyMap`, `ClientPropertyMap`, `CardImage`, `PendingPhoto`
- `features/public/v2/PropertyMedia.tsx`
- No incluye `propiedades/[slug]/opengraph-image.tsx` (va con SEO).

**Lote B: secciones `contact`, `appraisal`, `searchAlert` y `booking`**
- `app/[locale]/(public)/contacto/page.tsx`, `tasar/page.tsx`, `agendar/[id]/page.tsx`
- `features/public/v2/`: `ContactForm`, `PropertyContact`, `ContactClose`, `AppraisalForm`, `AppraisalBand`, `SearchAlert`, `AlertTile`, `formParts`
- `features/booking/BookingForm.tsx`, `features/booking/createBookingAction.ts`
- `features/actions/`: `createContactLeadAction.tsx`, `createLeadActions.ts`, `createAppraisalLeadAction.tsx`, `createSearchAlertAction.ts` (solo los mensajes al visitante; las notas del lead siguen en español)
- `features/public/searchCriteria.ts`: `describeCriteria` sigue en español (nota del lead); los chips del diálogo de alerta se traducen en `SearchAlert.tsx` usando `criteriaChips` (que trae `key` e `item`).

**Lote C: secciones `common`, `home`, `about` y `zones`**
- `app/[locale]/layout.tsx` (metadata), `app/[locale]/(public)/layout.tsx`, `page.tsx` (home), `nosotros/page.tsx`, `zonas/[zona]/page.tsx`, `error.tsx`, `not-found.tsx`
- `features/public/v2/`: `SiteFooter`, `Hero`, `HeroSearch`, `FeaturedListings`, `TypeShowcase`, `TrustSection`, `NotFoundContent`, `StatusPage`, `ChoiceGroup`, `content.ts`, `propertyTypes.ts`
- `features/public/zones.ts`
- `content.ts`: los textos de marketing (estadísticas, testimonios, pasos, valores) pasan a mensajes; `CONTACT_CTA_LABEL` se elimina recién cuando ya nadie lo importa (lo hace la revisión final, no el lote C).

**Ya migrados (no tocar):** `SiteHeader.tsx`, `LocaleSwitcher.tsx`, `zonas/page.tsx`.
